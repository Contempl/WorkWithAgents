# Панель проектов

Реализованы [тикет #2](https://github.com/Contempl/WorkWithAgents/issues/2), [тикет #3](https://github.com/Contempl/WorkWithAgents/issues/3) и [тикет #4](https://github.com/Contempl/WorkWithAgents/issues/4): сохранение регистраций Project, запуск команд из указанных папок, просмотр stdout/stderr, остановка деревьев процессов, редактирование и удаление регистраций, обработка ошибок и восстановление после завершения Panel.

Нужны Windows 10 или новее, Go и Node.js/npm в PATH. Реализация проверена с Go 1.27.4, Node.js 24.13.1 и установленным Microsoft Edge. Сервер написан на Go, интерфейс — на React и TypeScript, сборка интерфейса — Vite.

Из `cases/process-panel/` один раз установите зависимости:

```powershell
npm ci
```

Команда запуска и адрес заданы в [AGENTS.md](AGENTS.md#startup-contract). `npm start` проверяет доступность адреса, собирает интерфейс и Go-сервер и запускает Panel. При занятом адресе запуск завершится с понятной ошибкой до сборки, существующий сервис продолжит работать. Go-сервер также самостоятельно проверяет адрес при привязке.

Для ручной проверки добавьте проект:

- Название: `Учебный сайт`.
- Папка: абсолютный путь к `cases/process-panel/examples/learning-site` в этом репозитории.
- Команда: `node server.mjs`.

Нажмите «Запустить», дождитесь вывода о готовности и откройте [учебный сайт](http://127.0.0.1:4100). Команда `node server.mjs 4200` использует другой порт. Если Node.js отсутствует в PATH, укажите полный путь к `node.exe` в двойных кавычках.

Нажмите «Остановить»: сайт должен перестать отвечать, вывод останется виден. Учебная программа запускает HTTP-сервер дочерним процессом; остановка проверяет всё дерево. Команды выполняются через `cmd.exe /d /s /c`, stdout и stderr объединяются. «Работает» означает наличие активной программы, готовность произвольного приложения Panel не определяет.

Кнопка «Копировать вывод» в карточке Project копирует весь доступный вывод с переносами строк, включая сохранённый вывод после остановки ([тикет #5](https://github.com/Contempl/WorkWithAgents/issues/5)). При пустом выводе кнопка недоступна. Вывод хранится до следующего запуска Project или завершения Panel. Если браузер отклоняет копирование, карточка показывает ошибку и позволяет повторить попытку.

Разные проекты могут работать одновременно; остановка одного не останавливает другой. Редактирование и удаление доступны, когда у Project нет активного запуска. Чтобы изменить название, папку или команду, нажмите «Редактировать», затем «Сохранить». «Отмена» сохраняет прежние настройки. Удаление требует подтверждения и убирает только регистрацию: папка и файлы Project остаются на диске.

Обновление страницы сохраняет текущее состояние. Закрытие вкладки оставляет Go-сервер работать. Для выключения используйте Ctrl+C в терминале запуска. После следующего запуска Panel восстанавливает список, оставляя все проекты остановленными и без старого вывода. Каждый проект нужно запускать вручную.

Если программа завершается с ненулевым кодом, Panel показывает «Ошибка», код завершения и доступный вывод. Если остановка не удалась или завершение процессов не подтвердилось за 5 секунд, Project остаётся под управлением Panel: новый запуск, редактирование и удаление заблокированы, остановку можно повторить. Состояние «Остановлен» появляется после подтверждения завершения всего дерева.

При потере связи интерфейс сообщает об этом и блокирует действия с проектами. Показанное состояние считается последним известным. Открытая страница автоматически получает актуальное состояние после запуска Panel. При штатном завершении сам Go-сервер подтверждает очистку сообщением «Панель остановлена.»; если подтвердить её не удалось, он выводит причину и завершает работу с кодом ошибки.

Регистрации хранятся в `cases/process-panel/data/projects.json` рядом с кодом, на диске проекта. Каталог `data` исключён из Git. При необходимости задайте другой каталог через переменную окружения `PROCESS_PANEL_DATA_DIR` перед запуском. Для переноса списка после выключения Panel скопируйте `projects.json` в каталог данных другой копии Panel.

Добавление, редактирование и удаление подтверждаются только после записи файла. При ошибке сохранения текущий список не изменяется. Повреждённый или недоступный файл не заменяется пустым: Panel завершает запуск с объяснением ошибки. Запись сначала готовится во временном файле в том же каталоге, затем заменяет основной файл через [MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw). Состояния процессов и вывод в этот файл не записываются.

Проверки:

```powershell
npm run typecheck
npm test
```

`npm test` собирает приложение и выполняет системные проверки через настоящий Edge и учебные процессы. Edge должен быть установлен; браузер отдельно не скачивается. Проверки занимают адрес Panel и свободные временные учебные порты. Если адрес Panel уже занят, сначала завершите свой экземпляр обычным способом. Проверяющий стенд завершает только созданные им процессы. Каталоги проверочных данных создаются в `test-results/fixtures` внутри проекта; личный список из `data` не используется. Для выборочного запуска сначала выполните `npm run build` и `npm run test:prepare`, затем `npx playwright test --grep "часть названия"`.

Покрытие [спецификации #1](https://github.com/Contempl/WorkWithAgents/issues/1) системными сценариями:

| Сценарий | Наблюдаемая проверка |
| --- | --- |
| Запуск и остановка учебного Project | Браузер, stdout/stderr, состояния, ответ HTTP до остановки, отсутствие ответа и завершение потомков после неё. |
| Регистрации и постоянный список | Изменение названия, папки и команды; штатный перезапуск; удаление только регистрации с сохранением файлов. |
| Независимая работа | Два настоящих дерева, раздельный вывод, остановка одного без влияния на другое; защита от повторного запуска и изменения активной регистрации через UI и API. |
| Копирование вывода | Настоящий буфер обмена Edge: весь вывод выбранного Project с пустыми строками, пробелами, кириллицей и stderr при работе, после остановки и обновления страницы; пустой вывод и следующий запуск отключают кнопку. Отказ записи проверяется подменой только операции буфера обмена с последующим успешным повтором. |
| Ошибки запуска и программы | Несуществующая команда, занятый учебный порт с контрольным сервером, ошибка CreateProcess после перемещения папки, выход программы с кодом 7 и сохранением вывода. |
| Ошибки остановки | Отказ запроса и отсутствие подтверждения завершения; процесс продолжает отвечать, кнопки и API сохраняют ограничения, повторная остановка завершает дерево. |
| Возврат пользователя | Закрытие, повторное открытие и обновление вкладки сохраняют текущую программу и вывод. |
| Выключение и авария Panel | Для двух проектов проверены завершение всех учебных PID и HTTP, сохранность независимого контрольного сервера и восстановление регистраций без автозапуска и старого вывода. |
| Связь с сервером | Открытая страница замечает потерю связи, блокирует действия и восстанавливает актуальное состояние при возвращении Panel. |
| Занятый адрес Panel | Отказ Go-сервера и стартового скрипта без вмешательства в чужой HTTP-сервис; стартовый скрипт проверяет адрес до сборки. |
| Согласованная команда запуска | Настоящий `npm start` собирает и запускает Panel; Ctrl+C позволяет Go-серверу подтвердить очистку и штатно завершиться. |
| Локальная привязка | Доступен IPv4 loopback; запросы к IPv6 loopback и другим доступным локальным интерфейсам не получают ответ; чужой Host отклоняется. |
| Ошибки хранения | Отказ записи не меняет список; повреждённый файл останавливает запуск и остаётся нетронутым. |

Отказ API остановки и отсутствие подтверждения воспроизводятся в отдельном `panel-fault-test.exe`, собранном с тегом `panelfaults`. Подменяется только результат одного запроса остановки, остальные операции выполняются над реальными Windows-процессами. Естественный отказ Windows API с отказом доступа не воспроизводился. Обычный `panel.exe` не содержит этого переключателя. Дополнительно проверяется, что неудачная очистка при выключении даёт ошибку в терминале и ненулевой код выхода, а закрытие Job Object при выходе завершает оставшееся дерево.

Отдельная первичная Windows-проверка опубликована в ветке [prototype/process-panel-windows-job](https://github.com/Contempl/WorkWithAgents/tree/prototype/process-panel-windows-job/cases/process-panel/windows-job-probe), коммит `9da8526`. Она проверяет обычную остановку, аварийное завершение управляющей программы и сохранность отдельного контрольного HTTP-сервера. Используются Job Objects с назначением при создании процесса и завершением группы при закрытии последнего дескриптора. Не проверены программы, которые делегируют запуск внешним службам или планировщику Windows. Выход Windows из сеанса, выключение компьютера и отказ питания отдельно не проверялись; основная проверка штатного завершения использует Ctrl+C, аварийного — принудительное завершение созданного стендом Go-сервера.
