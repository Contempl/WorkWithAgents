# Панель проектов

Реализованы [тикет #2](https://github.com/Contempl/WorkWithAgents/issues/2) и [тикет #3](https://github.com/Contempl/WorkWithAgents/issues/3): сохранение регистраций Project, запуск команд из указанных папок, просмотр stdout/stderr, остановка деревьев процессов, редактирование и удаление регистраций.

Нужны Windows 10 или новее, Go и Node.js/npm в PATH. Реализация проверена с Go 1.27.4, Node.js 24.13.1 и установленным Microsoft Edge. Сервер написан на Go, интерфейс — на React и TypeScript, сборка интерфейса — Vite.

Из `cases/process-panel/` один раз установите зависимости:

```powershell
npm ci
```

Команда запуска и адрес заданы в [AGENTS.md](AGENTS.md#startup-contract). `npm start` собирает интерфейс и Go-сервер и запускает Panel. При занятом адресе запуск завершится с ошибкой, существующий сервис продолжит работать.

Для ручной проверки добавьте проект:

- Название: `Учебный сайт`.
- Папка: абсолютный путь к `cases/process-panel/examples/learning-site` в этом репозитории.
- Команда: `node server.mjs`.

Нажмите «Запустить», дождитесь вывода о готовности и откройте [учебный сайт](http://127.0.0.1:4100). Команда `node server.mjs 4200` использует другой порт. Если Node.js отсутствует в PATH, укажите полный путь к `node.exe` в двойных кавычках.

Нажмите «Остановить»: сайт должен перестать отвечать, вывод останется виден. Учебная программа запускает HTTP-сервер дочерним процессом; остановка проверяет всё дерево. Команды выполняются через `cmd.exe /d /s /c`, stdout и stderr объединяются. «Работает» означает наличие активной программы, готовность произвольного приложения Panel не определяет.

Разные проекты могут работать одновременно; остановка одного не останавливает другой. Редактирование и удаление доступны, когда у Project нет активного запуска. Чтобы изменить название, папку или команду, нажмите «Редактировать», затем «Сохранить». «Отмена» сохраняет прежние настройки. Удаление требует подтверждения и убирает только регистрацию: папка и файлы Project остаются на диске.

Обновление страницы сохраняет текущее состояние. Закрытие вкладки оставляет Go-сервер работать. Для выключения используйте Ctrl+C в терминале запуска. После следующего запуска Panel восстанавливает список, оставляя все проекты остановленными и без старого вывода. Каждый проект нужно запускать вручную.

Регистрации хранятся в `cases/process-panel/data/projects.json` рядом с кодом, на диске проекта. Каталог `data` исключён из Git. При необходимости задайте другой каталог через переменную окружения `PROCESS_PANEL_DATA_DIR` перед запуском. Для переноса списка после выключения Panel скопируйте `projects.json` в каталог данных другой копии Panel.

Добавление, редактирование и удаление подтверждаются только после записи файла. При ошибке сохранения текущий список не изменяется. Повреждённый или недоступный файл не заменяется пустым: Panel завершает запуск с объяснением ошибки. Запись сначала готовится во временном файле в том же каталоге, затем заменяет основной файл через [MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw). Состояния процессов и вывод в этот файл не записываются.

Проверки:

```powershell
npm run typecheck
npm test
```

`npm test` собирает приложение и выполняет системные проверки через настоящий Edge и учебные процессы. Edge должен быть установлен; браузер отдельно не скачивается. Проверки занимают адрес Panel и свободные временные учебные порты. Если адрес Panel уже занят, сначала завершите свой экземпляр обычным способом. Проверяющий стенд завершает только созданные им процессы. Каталоги проверочных данных создаются в `test-results/fixtures` внутри проекта; личный список из `data` не используется. Для выборочного запуска сначала выполните `npm run build` и `npm run test:prepare`, затем `npx playwright test --grep "часть названия"`.

Отдельная первичная Windows-проверка сохранена в локальной ветке `prototype/process-panel-windows-job`, коммит `9da8526`, каталог `cases/process-panel/windows-job-probe`. Она проверяет обычную остановку, аварийное завершение управляющей программы и сохранность отдельного контрольного HTTP-сервера. Используются Job Objects с назначением при создании процесса и завершением группы при закрытии последнего дескриптора. Не проверены программы, которые делегируют запуск внешним службам или планировщику Windows.
